# P0/P1 本地搜索、筛选与 OCR 复核

本轮发现并修复 **1 个已纳入修复函数的额外分支差异**：搜索记录创建时的内容类型提前缩窄。查询、筛选、延迟正文和 OCR 队列的相符实现继续复用。

## 已修复差异

原版 `371998` 在 `371cd8` 读取完整 rawType，紧接着在 `371cdc` 调用 `323594`。后者的 64 位无符号比较仅接受 0～5；其余返回无效标记，构造器再归为 Unknown。

Pasto 原先先用 `NSNumber.uint8Value` 取低 8 位，再校验枚举，导致 **257、-255 被误判为 Image，260 被误判为 Link**。现在先取 `int64Value`，通过 `UInt8(exactly:)` 检查后再创建枚举，越界值统一回 Unknown。仅改两行，不改数据模型、存储列、内容数据或其他类型读取路径。

该差异位于已计数的 `Paste:0x100371998`，因此本轮记 **新增修复分支 1 个、新增唯一修复函数 0 个**，不重复增加累计修复函数数。

## 相符实现复用

- 查询保留原空白裁剪、转义、同类筛选 OR/不同类 AND，以及 macOS 26.4 的 contentDescription 分支。
- 建议源分组独立调用与处理错误，排除已选筛选后再取每组 30 项。
- 索引记录保存元数据和类型，正文/图片延迟读取；闭包保存 coordinator、objectID 和创建时类型。每次正文读取新建私有上下文，复用原始数据解码和 typed-preview 回退，不读取旧的整项值归档。
- OCR 先按已有待处理集合筛选，再合并集合/追加队列，所以同批重复项保留。出队先移除 pending 标记，再读取当前记录；取消检查在取图片之前。
- 索引仅取 OCR 字词，以 ASCII 空格连接；写回保留记录元数据、去掉图片能力，原正文非空时以换行追加。空/成功识别执行冷却，缺记录/图片及错误不进入同一冷却尾。
- 停止时取消并等待 OCR，再清 task 句柄，不清待处理 ID。实际 SDK 正文回调执行后才截取 5000 字符；可选弱服务消失与 SDK 错误保持区分。

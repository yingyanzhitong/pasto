# P0/P1 分组操作批量复核

本轮核对新增、改名、换色、排序和本地分组删除，**未发现新的已确认差异，直接复用现有实现，未修改应用源码**。

| 操作 | 原版有限合同与当前实现核对结果 |
| --- | --- |
| 新增 | 同一新 List 先写标识/名称，再尝试永久 ID，随后写属性与类型；永久 ID 或编码错误不提前终止后续赋值。 |
| 改名 | 第一次读取名称交给回调修改，再读取当前名称比较；不同才设置。空名用原本地化默认标题，原生标签路径不裁剪空白。 |
| 换色 | 只有成功解码的 pinboard 属性接受修改；未变不写，编码失败仍按 optional 属性写入。八个原始颜色码与二进制表逐项一致。 |
| 排序 | 按原生 metadata.index 读取顺序并用对象相等定位，仅更新改变的位置；后台上下文触碰 metadata，保存前安装通知观察，结束后移除。外层及上下文内分别弱读所有者，缺失时各自退出。 |
| 删除 | 本地 type2 分组中，匹配的 owner 先解除；同时没有历史 timestamp 和 owner 的项目删除，历史项目保留；最后删除所选 List。查询失败按空序列处理。 |

真实界面动作使用选中的原生 List 实体进入事务，不重新用名称或 UUID 猜目标。排序继续使用已显示的标签位置完成本地移动，持久化事务出错时仍保持原有本地移动流程。

你指定的两项适配保持：新增优先使用尚未用过的颜色；非空分组的删除确认与错误留在面板内。原版随机选色和模态弹窗未被当作必须恢复的行为。

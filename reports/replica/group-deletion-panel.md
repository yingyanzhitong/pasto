# 分组删除：条件对照与面板内操作

2026-10-29。已更新本机 `/Applications/Pasto.app`，未提交、推送或发布。

## 原版证据

- `0x100021f00` 构建分组菜单，结合 `0x100325130` 的数量判断决定删除项是否带省略号。
- `0x1003c4f00`：普通本地空分组直接进入删除事务；非空分组先确认。共享类型另有分支，本轮不将本地分组适配计为共享分组验收。
- `0x100022ad0 → 0x1003b6cfc` 实际创建并运行 `NSAlert.runModal`，会激活应用。因此“原版完全不弹系统确认”并非本次反编译证据支持的结论。
- `0x100368818 → 0x100363004` 清理分组关联并删除组对象；记录仍有历史时间或其他归属时保留，无历史及归属时清理。Pasto 既有仓储支持多分组关系，本轮保留其兼容行为，没有把所有组内记录改写为历史记录。

本轮按用户要求将确认呈现改为**底部面板内部**，采用上述删除条件和内容保留规则。这一内嵌呈现是用户指定适配，不伪称原厂控件或布局逐句迁移。

## 修改

- 空组菜单显示“删除”，直接执行；非空组显示“删除…”，在卡片区域显示紧凑确认。未调用 `NSAlert` 或创建额外窗口。
- 提示准确说明：历史及其他分组中的内容保留，仅属于该分组的内容删除。
- 取消、Esc 或点确认区域外的卡片背景只撤销确认；切换分组或关闭面板会清理待确认状态。
- 确认期间拦截卡片复制、删除和导航快捷键，避免对背景内容误操作；保留确认按钮的焦点导航。
- 保存成功后才更新视图：删除当前组返回历史，删除其他组保留当前组。保存失败在确认区域显示错误，不另开提示窗或误切分组。

## 验证与范围

原生 UI 隔离回归通过，使用临时数据库、私有剪贴板和合成内容：覆盖空/非空组、取消与 Esc、背景快捷键拦截、切组取消、当前/其他组删除、历史及多组归属保留、仅本组内容清理、重新加载，以及关闭后清除待确认状态。

通过临时 SQLite 触发器注入删除保存失败，验证回滚、原分组与内容保留、原位错误提示和后续事务可复用。日志中的对应 Core Data 错误是这项预期失败注入，不作为成功删除记录。

本机实际打开非空分组删除入口，观察确认在原底部面板内；点击“取消”和按 Esc 后确认消失、面板及分组仍在。未对真实分组执行删除提交。SDK 26.5 Release 构建、代码签名、源码/安装二进制一致性、单进程、SQLite 完整性、既有记录/分组及偏好保留检查通过；旧应用 ZIP 备份核验后移除。

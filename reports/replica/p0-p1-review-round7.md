## 新增结论及其边界

本轮继续第六轮全部 32 个未闭合地址，新增 **12 项有限一致、4 项具体差异**。不以“没有相同的原寄存器 ABI”否定已经证明的薄转发；也不把薄转发的局部一致外推为被调模块全部一致。

- **恢复事务薄闭包 `37b620`。** ARM 证明 caller 将原选择数组及 manager 成对放入 closure 捕获槽，函数仅载入两槽、调用 `37ade4` 后返回。当前有效、未删除的选择 ID 保序直接交同步恢复事务。这里闭合捕获与交接合同；历史清理、保存失败后续等已知父链差异仍然保留。
- **搜索 payload、popover 和输入路由。** `021e40` 只比较 search payload 的所有权释放副作用；`03f044` 只比较显示/关闭、Option 标志和回调接线；`041860`、`041e08`、`099adc` 只闭合存活期间的完整 query/identifier 交付。原 weak owner 失效门与当前强 state/view 捕获生命周期**没有**因此判为一致，未覆盖边界已单列为结构化字段。
- **单选目的列表 `3b83c4`。** 有限正常列表域中的单选检查、历史优先、owner 过滤和排除当前列表可对应。当前 `Pinboard.rawType=nil` 是旧 JSON 普通分组的兼容表示，实际 provider/导出按类型 2 处理。不能把它直接映射为原版 `rawType=0` 并制造差异反例。
- **创建适配器 `3c4e4c`。** 有效成功输入中的 UUID 标识、传入名称及普通分组字段桥可对应。UUID 生成与属性编码的先后、永久 ID 失败及上下文副作用不在本项一致范围内，`368560` 仍未闭合。
- **索引完成/调度/清理帧。** `2f217c`、`2f2268`、`360774`、`3607c4` 的有限完成交接或清理职责可以对应；未把持久状态或结果模型整体纳入这些叶子的一致结论。

## 抽查纠正与剩余工作

**`3b8bfc` 缓存返回对象，不能解释为只缓存 closure。** 原 C 的 `pcVar2` 表面保留函数地址，但 ARM `3b8c28` 调用 `35a864` 后，`3b8c2c` 接收返回值，`3b8c34` 将返回 `x0` 写入 owner `+0x10`。`35a864→35a89c` 会在 `performAndWait` 内执行 `35bb5c`/回调，返回生成的 provider/sequence 对象。原对象刷新链和当前 `visibleItems` 重新投影之间的行为关系尚未闭合，所以仍为未闭合。

**P0 只剩 `3611b0` 查重身份映射。** 原未知类型、无路径文件的归档 MD5 与当前表示内容比较还缺全输入身份映射。本轮排除了两个不成立的候选反例：当前显式容器比较保留 ordered types，不会仅因归一化函数存在就丢失类型顺序；原 `37d5c4` 读取首个格式的原始数据，不要求图像解码成功。不能用错误候选推动计数。

P1 剩余 15 项：`021f00`、`052734`、`06f29c`、`07e088`、`0f733c`、`2e00a0`、`2f2690`、`2f26a8`、`2f7744`、`2faafc`、`360808`、`3647d4`、`368560`、`3b8bfc`、`3bb540`。下一步优先追 provider/VM 的结果订阅连接、输入发布与菜单/拖放门控。无消费者的 `0f733c` 不按声明存在计为迁移完成。

## 原链路已定位

`0x100066068` 在 direct restore 成功后构造 Task，再调用 `NSApp.deactivate`。此前只有一个不透明 Task descriptor，不能据此猜测发送前需要固定延时或目标轮询。

本轮按 Mach-O 的 `__TEXT` 段映射读取描述符，验证原切片摘要仍为 `871f00354fbb1c165d858a98e6d19d6f43cb9d3f9f958b3e07c7f07eb5c19afb`：

- `0x100c26d68` 的 signed relative function offset 指向 `0x100076018`；闭包再调用 `0x100053988`。
- 默认 Task wrapper descriptor `0x100c26d78` 指向 `0x1000760b0`，经 `0x100071054` 按捕获的 descriptor 调用闭包。
- `0x100053988` 使用 MainActor executor 切换到 `0x100053a18`。
- `0x100053a18` 恢复后解析发送服务，调用 `0x100ae641c`。
- `0x100ae641c` 仅转发固定字符 `v` 到 `0x100ae6428`。

这条实际链路没有 Pasto 原来的“指定目标激活 → 50 ms 轮询 → 1 秒期限 → 代次/剪贴板变化拒绝”步骤。描述符原字节、段与文件偏移、目标及伪代码摘要均保存在 [机器记录](offline-migration-p0-round4.json)，没有加载执行原程序。

## 源码修正

成功恢复后创建强捕获 owner 的 MainActor Task，进入实际 async 方法调用固定 `v` 包装，随后走 `NSApp.deactivate` 与现有面板关闭。删除独立的 `waitForTarget`、显式目标激活/轮询、超时和由它引入的代次状态。

面板原有的 onWillClose → 激活上一应用 → 清空保存值继续保留；独立预览存在时不恢复的分支也保留。它位于 0.2 秒动画之前，不使用轮询重新设光标。普通 copy-only、私有剪贴板隔离路径及权限设置 raw2 当次提前结束仍在任务排队前返回。

为原 async 入口、resume、Task 闭包和固定字符包装新增 4 条 **partial** 源码映射，没有将 Swift 编译器生成的帧/continuation ABI 冒计为完整迁移，也没有冒用历史编译结果。原实例 DI、完整错误父合同及布局数据边界仍待证。

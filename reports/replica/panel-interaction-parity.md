## 原版证据

使用本地已导出的 REA/Ghidra 伪代码，它们不是厂商原始 Swift 源码。主要地址：

- `0x100079980`、`0x100079ba4`、`0x100079ca0`：TabBarCell 跟踪区和进入/退出。
- `0x100079da8`、`0x100079e98`、`0x10007a078`：按下、整块区域释放、编辑/按下/选中/悬停背景优先级。
- `0x1000791a0`：原标签焦点轮廓映射到整个分组单元；`0x1001ff12c`：5% 黑/白动态悬停色。
- `0x10000ce94`、`0x10000d050`、`0x10023e080`、`0x10023d784`：原生工具栏按钮及状态外观。
- `0x100039618` → `0x10003b4c0`：使用未命名默认标题创建，延迟 0.2 秒发送进入编辑事件。
- `0x100236978`：滚轮轴转换；`0x100221b40`：离屏单元进入复用集合并执行 prepareForReuse。Pasto 继续适配已有 SwiftUI 卡片架构，不宣称厂商视图类/工厂整体等价。
- `0x1003cb83c` 及 `0x100c0cba0`、`0x100c0c960`、`0x100c0cd80` 的 selector：原生滑杆最小值 1、最大值 5、五个刻度。
- `0x1003cbde4`、`0x1003cbf08`、`0x10035bb8c`、`0x10035ba90`：滑杆 action、结束跟踪及保留期限分段换算。独立实现对非有限/越界输入作安全拒绝，不将这类防护差异计为完整地址等价。
- 复制链路沿用 [18 个函数的对照](copy-original-flow-audit.md) 与 [Core Data 适配](copy-coredata-alignment.md)。

## SDK 是系统控件外观差异的重要原因

安装前的 Pasto Mach-O 记录 `SDK 15.2`，原版 Paste 为 `SDK 26.5`。仅添加 `UIDesignRequiresCompatibility = false` 的旧 SDK 隔离构建没有获得相同外观；使用真正的 26.5 SDK 重新构建后，原生滑杆、刻度、圆角分组容器及按钮已呈现系统新设计。未使用修改 Mach-O SDK 数值的方式伪装构建。

工具来自 Apple Software Update 的已签名 Command Line Tools 26.5 包，仅提取到 Git 忽略的本地目录，通过进程级环境使用；未全局安装或切换 Xcode，系统默认 SDK 仍为 15.2。新应用实际链接 SDK 为 26.5、最低运行版本仍为 macOS 14。后续 CI 源码已为 Intel 与 Apple 芯片任务选择可用的 Xcode 26.3，尚未提交或触发它们。

参考 Apple 的 [AppKit 新设计说明](https://developer.apple.com/videos/play/wwdc2025/310/) 和 [兼容模式配置说明](https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility)。新设计的实际颜色还受窗口是否处于活动状态和系统外观影响；隔离离屏窗口会显示非活动色。

- 最新 Release 构建、SDK 负载命令、签名和本机启动检查通过。升级前备份数据和旧应用；升级后 SQLite 完整性、记录与分组数量检查通过，同步保持关闭，保留期限仍为一周。旧应用副本在备份核验后移除，本机保留当前安装。
- 当前应用源码哈希在验证与安装之间保持不变。机器可读结果见 [验证记录](panel-interaction-parity.json)。

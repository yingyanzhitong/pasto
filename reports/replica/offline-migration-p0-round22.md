## 已修复

原 `2ea78c → 2eaa10 → 2eaea4` 先过滤空 ID，按原输入数组每 100 个 ID 获取实体；本批有实体才调用 SDK，空结果仍推进下一个输入区间。推进依据是输入 ID 数量，不是查到的实体数。原 slice 保留顺序与重复。

Pasto 原来把请求合成 UUID 集合，先读取全部目标实体，再按结果分批。现请求保留为有序 String 数组，只保留本 store 的 namespace 并过滤空 local ID，不再因提前 UUID 校验、去重或排序压缩区间。数据库接口接收原始 key 数组，逐区间 live fetch，构造本批 CSSearchableItem 并 await SDK 后才继续。

缺失实体或整批空结果不结束任务；SDK 错误直接向父传播，不读取后续批次，全部批次完成后才提交自有内存并完成应答。强制重建不受元数据相等判断影响。全量 reset 同批有指定 ID 时，仍在全量处理之后执行目标请求，不丢弃待办。全量/snapshot 保留独立策略，没有把本路径的上限套给未闭合的普通增量。

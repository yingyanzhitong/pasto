# 复制后面板收起延迟排查

> 此报告保留切换 Core Data 前的测量快照。最新实现及验证见 [Core Data 对齐报告](copy-coredata-alignment.md)。

日期：2026-10-29。范围：Pasto 本地复制路径；未安装、提交或发布。

## 结论

原有调用顺序是“写入剪贴板 → 更新时间并同步保存全量历史 JSON → 开始收起”。历史包含大体积图片或二进制内容时，JSON 编码、原子替换与文件同步发生在主线程，短文本复制也要等待全量保存。

本机只读取了历史文件体积，没有读取或上传用户剪贴板内容。测试独立生成约 72 MiB 历史，使用命名剪贴板和屏幕外窗口。

## 当前性能缓解（不是原版等价迁移）

- 剪贴板写入与采集循环防重计数仍在返回前完成；复制后立即启动收起动画，历史更新时间在动画结束、窗口关闭后保存。
- 保留原来的 0.2 秒动画。原版证据为 `decompiled/Paste/part-0010.c` 的 `0x100019a84`，时长常量 `0x3fc999999999999a`。
- 保存使用复制发生时的时间，保留倒序恢复语义，不覆盖间隔期间更新的编辑时间和内容。
- 快速重新打开面板会补齐待保存操作；正常退出在最终保存前执行同一补存函数。错误仍走原有提示路径。
- 普通直接粘贴及 MCP 等未传入调度器的调用保留同步保存行为。

## 原版实现复核

后续追踪已确认：Paste 的正常复制路径在关闭前通过 Core Data `performAndWait` 执行仓储更新，`hasChanges` 时调用 `save:`，随后清理 Undo、发送恢复通知并退出激活；没有把此事务挂到关闭动画完成回调。当前延后全量 JSON 的方案属于独立存储适配层优化，不能称为原版迁移。详细调用链、二进制保存 selector 与剩余差异见 [原版对照报告](copy-original-flow-audit.md)。

## 测量

Release 优化的 arm64 测试程序；修正前使用保存的旧 UI 调用链和同一份 Core。每种大小各 3 次，第一轮窗口初始化记作热身，以下为剩余 2 次的中位数。

| 指标（约 72 MiB 合成历史） | 修正前 | 修正后 |
| --- | ---: | ---: |
| 复制调用返回、剪贴板可用 | 216.07 ms | 1.58 ms |
| 窗口关闭通知 | 425.74 ms | 203.38 ms |
| 主线程观察到本次历史保存完成 | 430.91 ms | 563.73 ms |

收起耗时约减少 52.2%。这里改善的是面板响应；全量 JSON 保存仍然存在，整体保存耗时没有减少。没有对原版 Paste 进行实际运行计时，不能据此宣称与原版全部性能一致；样本也不足以代表所有负载。

## 校验

- 23 组核心回归通过：包含剪贴板立即可用、延后保存、并发编辑合并、时间顺序和无效选择不改写剪贴板。
- 原生屏幕外面板定向回归通过：覆盖实际 ⌘C 路由、关闭后落盘、关闭中再次复制、快速重开补存、旧动画回调隔离、Esc、点击外部与既有分组命中区。
- `Pasto` Release 目标构建通过。退出补存复用已由重开用例执行的函数，未操作已安装应用的退出流程。
- 原始测量和源码哈希见同目录 `copy-dismiss-latency.json`。本地基准脚本、编译日志保存在忽略的 `.local/copy-dismiss-latency/`。

## 本轮实质结论

- **复制门禁**：沿 `31c4c4 → 31c504 → 31c38c → 1a15c4` 追到原 `License` 类型。类型名通过 nominal descriptor 的相对指针和静态字符串核实。`3b936c`、`066068` 的 `allSatisfy` 真分支进入原 Paywall；false 分支继续本地动作。Pasto 根据用户要求提供免费独立软件，省略该授权门禁，记为两项指定适配。原恢复事务 `37a144` 等仍未闭合，不因此算一致。
- **分组类型**：`31bc94` 原 getter 仅在所属 list 的 `rawType == 2` 时返回；当前 `ClipboardStore.pinboardOwner(for:)` 只按 ID 查找，未做类型过滤，记为明确差异。不得将其泛称用户批准的模型适配。
- **监听器**：`031978` 原方法每次调用都安装 keyDown monitor 并替换 token；当前已有 token 就返回。单次正常显示不因此判失败，但重复调用分支确有差异。
- **异步寿命**：`2f65e0` 原回调创建 MainActor Task 时强持有 owner；当前嵌套 Task 再次弱捕获。owner 在排队后释放时，两者可能分别继续或跳过 flush。该方法记为明确差异，定时器父链 `2f60fc` 和转发 `2f6f0c` 保留未闭合。
- **可复用方法**：核对筛选节点增删、候选顺序、有效三列导航、搜索输入历史、Stack 表格回调、富文本首 run 决策及撤销范围、OCR 错误与逐词范围行为。每项绑定原函数全文摘要、当前方法和实际消费者；局部一致不外推为完整模块一致。
- **静态符号槽**：逐个解码 11 个 getter 的 ARM64 ADRP/ADD/RET 地址及 Swift 小串/长串存储，匹配当前稳定字符串槽和图标消费者。此结论不要求两个进程的指针数值相同。

分组初稿中“完整菜单只看颜色分支”“新建分组原版是弹窗”“架构改变均属用户适配”等判断已撤回。原新建链同样是创建后延迟 0.2 秒进入原位编辑；创建事务仍待证。明确指定的分组适配仅保留未用色优先和面板内删除确认。

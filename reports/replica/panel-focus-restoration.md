# 面板关闭后的输入焦点恢复

日期：2026-10-29。已修复并更新本机 `/Applications/Pasto.app`，未提交、推送或发布。

## 原版调用链

依据本地 REA/Ghidra 导出的伪代码，而非原厂原始 Swift 源码：

1. `0x1000b07f0` 将 AppDelegate 的显示/关闭回调连接到 AppCoordinator。
2. `0x1000b098c` 在面板显示路径保存前台应用到 `handoffPreviousApp`，随后激活 Paste。
3. `0x100019a84` 在关闭动画开始前发出窗口关闭通知并调用 `onWillClose`。
4. `0x1000a56f4` 注册的回调经 `0x1000a9968` → `0x1000a82fc` 转回 AppDelegate 的 `0x1000b11ac`。
5. `0x1000b11ac` 在没有独立预览窗口时，对保存的应用执行 `activateWithOptions:2`，随后清空保存值；存在预览时只清空保存值。
6. `0x1000a8700` 的快捷键开关在面板可见且未关闭时调用相同的关闭入口。

Pasto 已实现开关和动画，但此前没有这一对显示/关闭交接回调：打开时激活了 Pasto，关闭时仅关闭窗口，未恢复原输入应用。这与用户反馈的光标消失相符。

## 修改

- `ReplicaUIController` 增加显示前与关闭时回调。关闭回调位于通知之后、0.2 秒动画之前，并传递独立预览是否为空；重复关闭继续由原有关闭状态保护。
- `ReplicaAppDelegate` 保存打开前应用，关闭时按原版选项恢复应用，然后清空保存值；不对输入内容或选区执行替换、重设或模拟点击。
- 当前 Pasto 在显示动画前就激活应用，因此在激活前保存前台应用；菜单栏或重开入口已经激活 Pasto 时，必要时使用已有粘贴目标作为回退。对已退出进程作安全跳过。这些是独立应用入口的适配，不将其称为原版整个 Handoff 系统的逐函数等价迁移。

## 验证

- 原生面板回归通过，新增同入口开关、关闭动画前回调、重复关闭只恢复一次、独立预览存在时不恢复等检查。已有复制、双击私有剪贴板写入、标签点击、分组编辑、Escape、外部点击和快速重开检查仍通过。
- 本机文本编辑合成文稿中，使用现有快捷键打开、再用相同快捷键关闭，直接按键续写；三轮后文本由 `Pasto cursor baseline` 变为 `Pasto cursor baselinexyz`，中间未重新点击文本框。
- 将光标左移三位，再次开关后输入 `m`，得到 `Pasto cursor baselinemxyz`，确认没有把原插入位置重设到末尾。测试使用 CUA 的应用键盘操作，不等同于所有应用与输入法的物理键盘验收。
- 使用 SDK 26.5 构建并更新本机，签名及源码/安装二进制哈希校验通过；SQLite 完整性、已有记录/分组保留及偏好一致性通过。旧应用已备份并移除临时副本；合成测试文稿已丢弃。

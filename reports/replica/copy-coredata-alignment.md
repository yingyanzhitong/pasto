# 复制保存链路：Core Data 对齐与验证

日期：2026-10-29。范围为本地源码，不安装、提交或发布，不恢复全函数持续迁移任务。

## 实现

依据 [18 个原函数的逆向证据](copy-original-flow-audit.md)，将复制路径恢复为：

1. 刷新并校验选中内容，生成表示，写入剪贴板并更新防重复采集计数。
2. 在 Core Data 主队列 context 的 `performAndWait` 内处理记录变更，`hasChanges` 时 `save()`。
3. 保存成功后清理共享 UndoManager，发出恢复通知。
4. 显示复制反馈，`NSApp.deactivate`，进入既有 0.2 秒关闭动画。

不再使用关闭动画完成后的保存调度器，也不在复制前额外保存一遍。保存失败时不会清理 Undo、发恢复通知，复制动作也不会继续执行成功反馈和收起步骤；原版是在事务前写剪贴板，因此保存失败时剪贴板可能已经变更，这个顺序被保留。

## 增量存储与兼容

- 活动存储为自有 Core Data / SQLite 模型，文件为原数据目录中的 `clipboard.sqlite`。原有 UUID、分组归属、来源、设置与归档字段保持兼容。
- 记录的复制时间与内容字节分开存储；仅时间变化时不编码内容。只更新有变化的实体，未选中的二进制内容不重写。较大内容由 Core Data 的外部二进制属性管理。
- CloudKit 文档、本地基线逐记录保存；待发送状态和检查点在同一次本地事务提交。仅复制时复用已知未变的附件，payload 改动后重新生成；缓存结果与全量生成结果已对照。
- `.lock` 的跨进程 `flock` 继续覆盖读取、三方合并、事务与发布；修订 UUID 用于检测其他进程的变更。失败回滚，不发布未保存的内存状态。
- 首次成功的数据库事务作为迁移标记。旧 `clipboard.json` 原样保留；失败可以修复输入后重试，删除记录后重开不会重新导入备份。导入导出仍使用兼容 JSON 归档。
- 升级前应退出仍写 JSON 的旧应用/工具；迁移后数据库是唯一活动存储，不反向合并旧 JSON 的后续修改。数据库及 WAL 共同组成活动状态，不能只复制 SQLite 主文件备份。

## 验证

- 25 组核心测试通过：含旧归档迁移及失败重试、16 MiB 二进制完整、无变化不保存、未选中实体不更新、真实 SQLite 保存失败注入、事务回滚、Undo 清理顺序、恢复通知前重开可见、无效选择不额外保存、两独立进程并发写入。
- 原生面板测试通过：实际 Command+C 路由中先保存/恢复通知再复制反馈，关闭中再次复制与快速重开、Esc、外部窗口点击、选择与分组行为。
- 分组迁移回归通过；33 项独立 iCloud Drive 本地检查及 67 项 CloudKit 隔离合同通过，不访问真实云服务。
- `Pasto` Release 目标构建通过；独立 Release 复制/关闭性能脚本通过。
- 补充真实 AppKit 后台采集检查通过：在临时应用身份、临时数据库与私有剪贴板中采集合成 Unicode 文本，验证生成内容过滤。测试观察器通过 `ClipboardStore` API 读取，不解析 Core Data 的私有 BLOB 布局；不操作已安装应用。
- 同一轮验证前后检查所有应用 Swift 源码和测试输入哈希，确认测试期间源码未变。机器可读结果见 [验证记录](copy-coredata-alignment.json)。

## 性能

使用合成记录、私有剪贴板与屏幕外窗口。大场景包含 54 个 1 MiB 二进制记录，JSON 等价体积约 72 MiB。每种场景运行三次，首轮作为窗口热身，以下为其余两次的中位数。时间包含系统调度，样本很少，不是性能保证。

| 场景 | 复制调用返回 | 恢复通知（保存后） | 窗口关闭 |
| --- | ---: | ---: | ---: |
| 空二进制历史 | 4.79 ms | 4.42 ms | 217.42 ms |
| 约 72 MiB 历史 | 5.15 ms | 4.45 ms | 224.30 ms |
| 相同大历史＋本地 CloudKit 日志 | 12.33 ms | 11.62 ms | 233.38 ms |

历史全量 JSON 版本的复制返回约 216.07 ms、关闭约 425.74 ms；上一轮延后保存版本约 1.58 / 203.38 ms，但历史处理被拖到关闭之后。本次恢复保存先于关闭，因此与延后保存方案相比，关闭前重新包含了少量事务开销。上述历史数字来自旧报告，不是本轮与原版运行时的同期基准。

## 等价边界与计数

已对齐的是有证据的本地保存粒度及恢复事务、Undo、通知、退出激活顺序。数据模型仍为 Pasto 既有 UUID 和值模型的独立适配，并非直接复用厂商数据库：完整列表迁移身份、共享分组、去重/清理策略及全部异常分支未因此自动闭合。检测到其他进程改动时，现有适配层仍会读取状态来完成三方合并；本轮不宣称原版完整惰性加载或所有负载的性能等价。

本轮新增完整原函数计数为 **0**，不把这 18 个参考函数或测试通过率冒计为 18 个完整迁移。全局历史台账仍为 **2.0315%（1,648 / 81,123，含过期摘要，未在本轮重审）**，不能作为本轮实时完成度。未运行原版性能测试，也未验证断电恢复、所有跨应用输入和全部原函数；没有触碰指定跳过的失败地址。

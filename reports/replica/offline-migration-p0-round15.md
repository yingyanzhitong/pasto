## 修复及复用

原 `031978` 在筛选 View 出现时安装匹配 `0x400`（keyDown）的本地监听，`0321d4` 在消失时移除。Pasto 原来只靠 SwiftUI 的 Return/Tab 回调，现补原生监听及清理，并删除重复键处理。

原 `031b60` 用物理键分类，只消费 Return 和 Tab。Return 从当前事件读取修饰键，传给 `032094`；Tab 根据当前事件的 `0xa0000`（Shift/Option）选择反向或正向移动。现在这两条路径使用 `event.modifierFlags`，键盘激活不再依赖全局按键状态；鼠标路径保留原全局修饰键读取。没有选中项时 Return 仍被消费，其他物理键继续传递；小键盘 Enter 不擅自并入原 Return 分类。

四方向导航已按原 `059768 / 059888 / 059a30 / 059ac0` 及坐标转换 `059b20 / 059ba4` 核对。当前三列、非空可见分区的生产输入域下，上一行、下一行、不完整末行裁剪、跨区保列及首尾循环与原公式一致，直接复用。可见条目的扁平化和每区计数来自同一 sections，也保留已有实现。

原坐标函数实际返回 section、row、column 三寄存器，无匹配时返回三个零；仅看 Ghidra 的单返回值会误读。原函数还允许通用 columns 参数，并包含负值、越界、除零和溢出陷阱。现有三列 UI 算法不能证明这些全部输入已迁移，因此相关映射保持 partial。

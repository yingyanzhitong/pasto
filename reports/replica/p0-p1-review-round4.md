## 本轮新增证据

- **新记录标识**：`360d9c` 原函数接受可选 String identifier。没有提供时，调用分类与 `3216bc` 计算校验和字符串；返回 nil 时走错误，非 nil 时把该字符串写入 identifier。ARM64 指令明确将返回的 `x0/x1` 保存为 `x26/x23`，后经桥接进入 `setIdentifier:`。当前采集构造 `ClipboardItem` 时使用默认 UUID，新建时保留此 ID。标识值域和默认生成规则不同，不是根据 C 临时变量名猜测。
- **来源读取**：解析 `AppRepositoryWriting` conformance、类型名和 witness 槽，绑定到 `35fbcc → 311e3c`。原版也先读取前台应用，并依次要求 bundle ID、名称、图标，和当前 snapshot 的三项门槛一致。这一旧疑点已消除；原仓库关系、事务错误与 callback 时点仍未闭合，相关父函数没有据此升级一致。
- **元类与模型接口**：从原 class 对象和 class_ro name 指针核实专用 `ItemEntity` 元类，真实消费者还读取该类的默认 fetch 方法。当前实体统一使用 `NSManagedObject`。原 `SearchableItemEntity` 的业务字段接口与当前八字段 Entry 也不同，特别是可选设备、单分组及延迟内容/图片闭包。记为模型接口差异，不以地址、类型改名或编译器布局差异本身充当产品问题。
- **菜单 action**：原删除闭包对 collection owner 使用弱引用，失效时 no-op；当前 action 使用 View 的 state，单项删除路径没有同一 controller 存活门。静态记录捕获与前置条件不同，没有宣称运行复现销毁后的菜单操作。
- **查询与状态**：补齐已生效查询的双流路由、pending focus 和水平偏移、建议应用算法等有限方法。原持久 IndexingState 的启动/恢复和 active 状态，与当前内存 `needsReset/indexed`、取消后重置策略存在差异；入口的结论绑定真实被调函数，不把 async 帧空间分配当作持久 I/O。

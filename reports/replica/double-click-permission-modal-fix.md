# 双击卡住：权限提示窗布局修复

日期：2026-10-29。已更新本机 `/Applications/Pasto.app`，未提交、推送或发布。

## 复现与根因

用本轮生成的合成文本在已安装应用中双击复现。日志停留在 `request ax=false post=false`，尚未到达剪贴板恢复完成。随后 AppKit 报 `NSGenericException`：窗口的约束更新次数超过视图数量，窗口类为 `PRGlassBackgroundWindow`。主线程采样仍可进入事件循环，但提示窗布局异常造成界面无法继续操作，不是本轮发现的 Core Data 保存耗时问题。

使用 SDK 26.5 跑原权限窗口回归，同样触发未捕获的异常并退出，形成可重复的修复前失败用例。此前测试主要覆盖离屏内容尺寸及快捷键，没有执行真实 `runModal`；旧 SDK 测试也没有暴露这条新系统布局路径。

## 原版证据与修改

对照本地 REA/Ghidra 导出的函数，而非原厂 Swift 源码：

- `0x10021dc14`：先创建玻璃视图，再初始化 NSWindow，最后通过父类安装玻璃视图。原 Pasto 在父类初始化后创建玻璃并挪入默认内容，顺序不一致；现按原版修正。
- `0x10021dad0` / `0x10021db74`：保留内容访问转发到玻璃视图，未移除玻璃外观。
- `0x100ae5684` / `0x100ae5794` / `0x100ae58d8`：保留提示内容的原生容器、四边约束和外观传递。

仅修正初始化顺序后，SDK 26.5 测试仍失败。真正阻断尺寸反馈的是给全内容提示窗的 `NSHostingView` 设置 `safeAreaRegions = []`：这类内容已提供自身边距，避免工具栏安全区改变宿主内容尺寸、宿主约束再次改变窗口尺寸而持续循环。这是 Pasto 当前 SwiftUI / AppKit 宿主的适配修复，不声称从原版证据中恢复出了相同的属性赋值。

没有扩大提示窗宽度，没有跳过权限检查，也没有把缺少授权改为静默自动粘贴。

## 验证

- 修复前：SDK 26.5 权限窗口测试以 `NSGenericException` / 退出码 134 失败。
- 修复后：玻璃内容替换、原有工具栏、圆角、280 点内容宽度及 Return/Escape 检查通过；新增三次真实模态循环，分别返回 0、1、2，均正常退出并关闭窗口，设有五秒看门狗。返回值检查不代替勾选“不要再问”的按钮状态验收。
- 原生面板回归通过，新增两次实际卡片 `mouseDown(clickCount: 2)` → 私有剪贴板写入 → 面板收起 → 重开检查。交付处理器使用合成私有剪贴板，不发送系统粘贴按键。
- 新版安装后实际双击合成内容，提示窗正常显示；点击“不是现在，复制到剪贴板”后提示窗和面板正常收起。临时文本编辑文稿中手动粘贴后，内容与合成文本一致；快捷键再次打开面板成功。
- 新进程验证期间未再记录上述约束/布局循环异常。临时文稿已丢弃。
- SDK 26.5 Release 构建及签名验证通过；源码哈希与安装构建一致。升级前备份数据和旧应用，升级后 SQLite 完整性、已有记录/分组保留和偏好一致性检查通过；移除临时旧应用副本。

系统当前对已安装 Pasto 的辅助功能检测仍为未授权，因此本轮实际验证的是权限提示和复制回退。有效授权后的跨应用自动粘贴未在这次本机验证中通过，不将它混称为完成。

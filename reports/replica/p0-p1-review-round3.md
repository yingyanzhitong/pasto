## 本轮确认的差异

- **候选来源**：原应用、设备、分组候选通过 Core Data fetch，包含关系条件、读取时点及错误传播。当前主要从内存快照产生候选，旧应用名另有兼容回退，不具备同一 fetch 错误合同。
- **旧分组类型**：原方法严格 `rawType == 2`；当前建议和卡片定位接纳 legacy `nil`。保留兼容代码，单列差异，不把所有架构兼容泛称用户指定适配。
- **索引字段**：原 device 是可选字符串、pinboard 是单个可选标识，content 是可选的延迟解析闭包；当前分别为非可选设备字符串、分组数组和立即生成的文本。可选日期及应用字段 getter 的有限值传递可以复用，不能因此认定整个构造一致。
- **请求与更新属性**：原 fetch factory 应用默认排序/谓词并设 batch size 20；当前底层 fetch 未设置这些默认值，搜索显示另在内存过滤排序。原 CSSearchableItem 构造写 `isUpdate`，当前未传入或设置该标志。
- **索引范围与生命周期**：原删除全部 index 数据，当前只删当前 domain；原 query 不包含当前额外 domain/UUID 投影。原 indexer 存在即处理委托，当前 `requested == nil` 会直接应答；原释放 indexer 后再 ack，当前 worker 仍持有对象时 ack。以上均为静态代码分支结论，没有声称运行复现。
